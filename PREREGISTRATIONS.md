# Pre-registrations and results

Every confirmatory test in this project was written down and committed to git **before** its data existed: hypothesis, data rule, statistic and success criteria. Each was run once, without re-tuning. Exploratory diagnostics got a written decision rule before they were run. The sections below are copied verbatim from the project log (only the author's name is replaced); the git history shows each was committed before the data it judges. The summary table is in [`RESULTS.md`](RESULTS.md).

# Round 1: richer pose-free features (H1)

### Pre-registration: M2 hypothesis H1 (written 2026-10-13, BEFORE recording any layout-v2 session)
- **H1:** with pose-free features, `gaze_blend` (iris xy + the 14 eye blendshapes = 18 features) with ridge alpha=100 has lower cross-session error than `gaze` (iris xy, 4 features) with ridge alpha=10.
- **Data:** three new sessions recorded with calibration layout `v2` (25 targets), at different times of day/lighting, each tagged with `--note`. **Inclusion rule, fixed now:** `meta.layout == "v2"` and window `[0,0,1470,956]`. No session is dropped after seeing results; a session is dropped only for an objective failure (< 80% valid frames, or the target-safety abort), logged with the reason.
- **Primary (confirmatory) analysis:** leave-one-session-out. For each v2 session, train on the pooled targets (calibration and held-out) of every *other* clean session (the older clean sessions plus the other v2 sessions) and test on **all 25 targets of the held-out session**. Unit of analysis = target. Per-target error = mean over frames of Euclidean error in degrees of visual angle. Both configs are evaluated on identical targets (paired).
- **Primary statistic:** mean of the per-target paired differences d = err(`gaze` a=10) - err(`gaze_blend` a=100) (positive favors H1), with a 95% bootstrap CI resampling targets (10,000 resamples, fixed seed).
- **Success criterion (all three required):** (a) the CI lower bound is > 0; (b) the mean improvement is >= 0.25 deg; (c) `gaze_blend` is better in at least 2 of the 3 held-out sessions. Otherwise H1 is reported as **not supported**, with no re-tuning on these sessions.
- **Caveats, stated up front:**
  - The three clean M1 sessions (including Independent analysis #2) suggested the hypothesis, and alpha=100 was also suggested by them; they are exploratory and never confirmatory.
  - The comparison changes features and alpha together, so a win does not say which caused it. Secondary diagnostic configs (reported, not part of the criterion): `gaze` alpha=100 and `gaze_blend` alpha=10.
  - Three sessions carry little session-level information. A secondary sensitivity analysis uses a two-level bootstrap (resample sessions, then targets).
  - Everything else computed is exploratory and labeled so (`confirmatory=0` in `results.csv`).

# Round 2: lighting (H2, H3)

### Pre-registration, round 2 (written 2026-10-13, BEFORE any round-2 session is recorded)
**Model (both hypotheses):** `gaze_a10` (iris xy, ridge alpha 10), the H1 reference and the simplest config. Secondary (reported, not in criteria): `gaze_blend_a100`, `iris_a1`.

**Session design: 4 new sessions, 2 existing sessions reused as training only.**
- New: **F2** (front-lit), **B2** (backlit), **D1**, **D2** (dim). All recorded with layout v2, the guided checklist, image saving on, lighting captured automatically. F2 and B2 after a break with the lighting set up from scratch (ideally another day than F/B); D1 and D2 at different times.
- Reused as training twins only (their H1-round results were seen, so they are never test data here): **F = `session_20261013_040451`** (front-lit, face 124 / background 79) and **B = `session_20261013_033128`** (backlit, face~78 / background~146 from its note). The existing dim session `035038` is exploratory and is not used (it suggested the threshold).
- **Inclusion by captured lighting only (fixed now):** F2: label front-lit, face within +-25% of 124 (93-155). B2: label backlit, face 60-97 and face/background < 0.6. D1 and D2: label dim, face 25-50 (below the gate, so recorded via the U override). A session outside its range, or with < 80% valid frames, is re-recorded (max 2 retries, reason logged). Extra qualifying sessions are ignored; selection is never by results.

**H2: calibrating in the lighting you will use beats a pool from other lighting.**
- For each test session T in {F2, B2}: train on all 25 targets of the **same-lighting twin** (F2 <- F, B2 <- B) versus the **other-lighting session** (F2 <- B, B2 <- F); test on all 25 targets of T. Equal training size (one session each), identical targets (paired).
- Statistic: mean over the 50 test targets of d = err(other-lighting) - err(same-lighting), degrees; 95% bootstrap CI over targets (10,000 resamples, seed 0). **Success (all three):** (a) CI lower bound > 0; (b) mean d >= 0.5 deg; (c) d > 0 in both test sessions. Secondary: two-level (session then target) CI.

**H3: sessions that pass the brightness gate (face >= 60/255) are more accurate than sessions below it.**
- Within-session: each session trains on its own 16 calibration targets and tests on its own 9 interior held-out targets. Groups: **gated = {F2, B2}**, **below gate = {D1, D2}** (18 targets each).
- Statistic: mean error(below) - mean error(gated), degrees, 95% bootstrap CI resampling targets within each group (10,000 resamples, seed 0). **Success (all three):** (a) CI lower bound > 0; (b) difference >= 1.5 deg; (c) every gated session has a lower mean error than every dim session (4 of 4 pairs).

**Clarification (implementation, 2026-10-13, before any round-2 recording):** the "front-lit" label itself requires face >= 100 and face/background >= 0.9, so the written F2 range "label front-lit and face 93-155" is effectively face **100-155**; the code applies both written conditions and the 93 lower bound is unreachable. No change in intent.

**Where the gate comes from:** the only three conditions measured so far (exploratory, within-session error): face brightness 37 -> 7.3-8.6 deg; 78 -> 3.0-3.5 deg; 124 -> 1.3-1.7 deg. 60 sits between the dim and backlit sessions (the geometric mean of 37 and 78 is about 54, rounded up); >= 100 is the recommended (non-blocking) level. It is a three-point inference and the 37-78 range is untested.

**Caveats (up front):** the threshold, the 0.5 and 1.5 deg margins and both hypotheses come from three exploratory sessions of one person in one room, so this tests "this user, this room", not a population. Two sessions per group carry little session-level information (hence the 4-of-4 and both-sessions guards and the two-level CI). F, B and the gated sessions also differ in the face/background ratio, a confound H3 cannot separate from brightness. Passing H3 shows below-60 sessions are worse, not that 60 is the exact optimum. Failing H2 or H3 is reported as not supported, with no re-tuning on these sessions. All other output is exploratory and labelled so.

# Round 3: head position (H4, H5)

### Pre-registration, round 3: head position (written 2026-10-13, BEFORE any position session is recorded and before any step-3 model code)
**Why:** the author observed that the live overlay only works in the position it was calibrated in. Cause in code: `gaze_overlay.py` fits on the latest session only, with `gaze` features (iris position only, no head pose or distance). Goal: Run should use all calibrations and stay accurate when the head moves.

**Two recording sets, so the model can be developed on real position data without touching the test data.**
- **Set A (development, record first):** 6 sessions in one sitting: **C** (normal, centre), **N** (near: about 10-15 cm closer), **R** (far: about 10-15 cm further back), **L** (shifted about 10 cm to your left, still facing the screen), **Rt** (shifted about 10 cm to your right), **Lo** (sitting about 8 cm lower / slouched). Free to use for exploration, tuning and choosing the candidate. Never confirmatory.
- **Set B (confirmatory, record later, ideally another day):** the same 6 positions plus **C2** (a second normal-centre session at the end), recorded only **after** the candidate model is frozen in a commit. Set B sessions that start before that commit can never be test data (enforced by timestamp in the harness, like round 2).
- All sessions: layout v2, guided checklist, **front-lit** (round-2 class F: face 100-155, ratio >= 0.9) so lighting is not a confound, images on, a note naming the position (e.g. "pos N"). The posture check will flag displaced positions; use U to override.

**Inclusion by measured position only (fixed now; notes are labels, not evidence).** Metrics are the medians over valid frames of `posture_metrics` (inter-iris distance as a fraction of frame width; face centre x, y in the unflipped frame), relative to the C session of the same set:
- N: distance >= 1.12 x C. R: distance <= 0.90 x C.
- L (user's left = larger x in the unflipped frame): x - C.x >= +0.07. Rt: x - C.x <= -0.07. Lo: y - C.y >= +0.07.
- C2: distance within +-5% of C and |x - C.x|, |y - C.y| <= 0.03.
- Every session: 25 targets, >= 80% valid frames, clean window, class F lighting. A session failing its rule is re-recorded (max 2 retries per slot, reason logged); extras are ignored; selection is never by results.

**Models.** Reference **REF = `gaze_a10`** (the current overlay model). **Candidate CAND:** exactly one config, chosen on set A (and earlier sessions) during M2 step 3 from (3a) pooled ridge with head-pose and iris-size distance features, or (3b) the 3D gaze ray intersected with the screen plane; frozen by name in code (`PREREG3_CANDIDATE`) in a commit before set B is recorded. The other step-3 variant is reported as secondary only.

**H4 (the problem is real): the current approach loses accuracy when the head moves.**
- REF trained on all 25 targets of set-B C only (what Run does today); tested on all 25 targets of each displaced session (N, R, L, Rt, Lo; 125 targets) versus all 25 targets of C2 (same position, re-recorded).
- Statistic: mean error(displaced) - mean error(C2), degrees; 95% bootstrap CI resampling targets within each group (10,000 resamples, seed 0). **Success (all three):** (a) CI lower bound > 0; (b) difference >= 1.0 deg; (c) at least 4 of the 5 displaced sessions have a higher mean error than C2.

**H5 (the fix): the frozen candidate, trained on all other calibrations, beats the reference trained on the same data on a held-out position.**
- Leave-one-position-out on set B: for each test session T in {N, R, L, Rt, Lo}, train both REF and CAND on **all set-A sessions plus every set-B session except T** (identical training pool), test on all 25 targets of T. Paired by target (125 pairs).
- Statistic: mean of d = err(REF) - err(CAND), degrees; 95% bootstrap CI over targets (10,000 resamples, seed 0); secondary two-level (session then target) CI. **Success (all three):** (a) CI lower bound > 0; (b) mean d >= 0.5 deg; (c) d > 0 in at least 4 of 5 test sessions.
- Reported, not criteria: CAND vs REF trained on C only (today's Run behaviour); CAND's held-out-position error minus its error on C2 (how much position cost is left); per-position breakdown; per-target bias vs spread.

**Caveats (up front):** one person, one room, one camera; positions are discrete and moderate (about 10-15 cm), not continuous movement; set B on the same desk may share the set-A set-up. The 0.5 and 1.0 deg margins are judgement calls, not derived from data. If H4 fails, H5 is still reported, but the motivation is weaker than observed. Failing H4 or H5 is reported as not supported, with no re-tuning on set B. Everything else is exploratory and labelled so.

### Head-transform check: decision rule (written 2026-10-13 evening, BEFORE computing anything; next step 1)
- **Question:** does the translation of MediaPipe's facial transformation matrix (`transform[:3, 3]`, canonical-face units ~cm) track the real head moves, where the eye-corner estimate (`head_x/y`) did not (set A free fit -4..-9 vs +-50.6 points/cm)?

- **Axes (fixed before looking at gaze):** map the transform translation to the image convention of `head_x/y` (x image-right, y image-down) by the sign of its frame-wise correlation with `head_x` / `head_y` on set B (an axis convention check, not an outcome). If |r| < 0.5 on either axis, report that as a failure of the transform to track position at all.
- **Primary statistic:** the same free least-squares fit as `diagnose_positions.py`: screen x, y (points) ~ 1 + iris (4) + yaw + pitch + head x + head y, over all set-B frames, once with the eye-corner `head_x/y` and once with the transform's (tx, ty) in cm. Ratio = fitted head coefficient / geometric prediction (x: -1/cm_per_px, y: +1/cm_per_px; ~50.6 points/cm on this screen).
- **Decision:** the transform **tracks head moves** if both its x and y ratios lie in **[0.5, 2.0]** (right sign, within a factor of 2). Then the geometric gaze-ray route is un-parked: the next step is a pre-registered geo model using the transform translation, tested on NEW position sessions (set B is used up). Otherwise it stays parked and automatic head adjustment goes via M3's click-based self-recalibration (and later a pose-invariant pretrained model, M2 step 8). - **Caveat:** in the free fit, the iris features partly absorb head movement (turning the head to face the screen changes them), so a ratio below 1 is expected even for a perfect head estimate; the 0.5 lower bound allows for this. The nominal moves are rough (no tape measure).
